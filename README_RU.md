# PayTrade | README

**PayTrade** — экосистема инструментов для Telegram, объединяющая маркетплейс, платёжную инфраструктуру, API и Python SDK.

Проект позволяет пользователям размещать и покупать товары, проводить сделки и взаимодействовать с продавцами. Разработчики могут подключать платёжные возможности PayTrade к собственным приложениям.

## 1. О проекте

PayTrade объединяет несколько направлений:

- **Маркетплейс** — площадка для продажи и покупки товаров.
- **Платежи** — оплата через Telegram Stars и внутренний баланс.
- **API** — возможность подключить PayTrade к сторонним приложениям.
- **Python SDK** — библиотека для удобной работы с API.
- **Telegram-бот** — основной интерфейс проекта.

PayTrade развивается как единая экосистема, в которой пользовательские и технические возможности дополняют друг друга.

## 2. Экосистема

Основные компоненты проекта:

- **Основной бот:** [@paytradebot](https://t.me/paytradebot)
- **Поддержка:** [@PayTradeSupportbot](https://t.me/PayTradeSupportbot)
- **API:** платёжный интерфейс для сторонних приложений.
- **Python SDK:** инструмент для интеграции API в Python-проекты.

## 3. Маркетплейс

Маркетплейс позволяет пользователям выступать как продавцами, так и покупателями.

Возможности площадки:

- Создание собственных предложений.
- Просмотр каталога товаров.
- Поиск по названию.
- Просмотр профилей продавцов.
- Покупка через внутренний баланс или Telegram Stars.
- Общение с другой стороной сделки.
- Подтверждение получения товара.
- Оставление отзывов.

Новые товары проходят проверку перед публикацией в каталоге.

## 4. Товары и каталог

### Размещение товаров

Для создания предложения продавец указывает название, добавляет фотографию и устанавливает цену в Telegram Stars.

На одного продавца предусмотрено ограничение — до 10 товаров.

### Управление товарами

Владелец предложения может:

- Изменить название.
- Изменить цену.
- Заменить фотографию.
- Удалить фотографию.
- Удалить товар.

### Каталог

В каталоге отображаются доступные для покупки предложения.

Пользователи могут просматривать товары, переходить между страницами и открывать подробную информацию.

Приоритетные предложения показываются выше обычных. Для товаров со скидкой отображается её размер и итоговая цена.

### Карточка товара

В карточке отображаются название, стоимость, информация о продавце и фотография, если она добавлена.

Отсюда можно перейти к покупке или открыть профиль продавца.

## 5. Покупки и сделки

В PayTrade предусмотрены два способа оплаты:

**Покупка через баланс**

Стоимость товара списывается с внутреннего баланса покупателя.

**Прямая покупка**

Покупатель оплачивает товар через Telegram Stars.

После успешной оплаты создаётся заказ и начинается взаимодействие между сторонами.

### Общение по заказу

Покупатель и продавец получают уведомления о покупке и могут обмениваться сообщениями через бота.

Продавец может сообщить о передаче товара, а покупатель — подтвердить его получение.

После подтверждения покупателем сделка завершается, а средства зачисляются продавцу.

Покупка собственного товара не поддерживается.

## 6. Баланс и отзывы

### Внутренний баланс

Баланс используется для оплаты товаров внутри маркетплейса.

Продавец получает средства за завершённую сделку после подтверждения получения товара покупателем.

### Отзывы

После завершения покупки покупатель может оценить продавца по пятибалльной шкале и оставить отзыв.

В профиле продавца доступна статистика оценок. Также можно просматривать отдельные отзывы с информацией о товаре, оценке и дате.

## 7. PayTrade API

**PayTrade API** позволяет разработчикам использовать платёжные возможности проекта в собственных приложениях.

С его помощью можно:

- Подключать свои приложения к PayTrade.
- Создавать платежи.
- Получать ссылки для оплаты.
- Проверять состояние платежей.
- Получать информацию о приложении.

Платежи проводятся в Telegram Stars (`XTR`).

### Как работает оплата

1. Ваше приложение создаёт заказ.
2. Через API создаётся платёж.
3. Приложение получает ссылку на оплату.
4. Покупатель переходит по ссылке в официальный бот PayTrade.
5. Покупатель оплачивает заказ.
6. Ваше приложение получает актуальную информацию о платеже.
7. После подтверждения оплаты ваше приложение выполняет необходимые действия.

PayTrade предоставляет платёжную инфраструктуру, а логика самого стороннего приложения остаётся под контролем его разработчика.

## 8. Python SDK

**PayTrade SDK** — официальная Python-библиотека для работы с API.

Текущий публичный релиз — **v0.2.0**.

SDK поддерживает асинхронную работу и предоставляет методы для:

- Подключения к API и получения информации о приложении (`me()`).
- Создания платежей (`create_payment()`, `payment()`).
- Получения информации о платеже (`get_payment()`).
- Отмены платежа (`cancel_payment()`).
- Ожидания результата оплаты (`wait_for_payment()`).
- Обработки ошибок API.

Библиотека подходит для асинхронных Python-проектов, включая Telegram-ботов на aiogram.

### Объект Payment

После создания или получения платежа SDK возвращает объект `Payment`.

Основные поля:

| Поле | Описание |
|---|---|
| `id` | Идентификатор платежа |
| `order_id` | Идентификатор заказа разработчика |
| `buyer_id` | Идентификатор покупателя, переданный при создании платежа |
| `amount` | Сумма платежа |
| `currency` | Валюта платежа |
| `title` | Название платежа |
| `description` | Описание платежа |
| `status` | Текущий статус |
| `created_at` | Время создания |
| `expires_at` | Время окончания срока действия |
| `paid_at` | Время оплаты, если платёж оплачен |
| `payment_url` | Ссылка для оплаты |
| `test_mode` | Признак тестового режима |

Дополнительно доступно свойство `paid`, возвращающее `True`, если статус платежа — `paid`.

### Статусы платежей

`wait_for_payment()` проверяет состояние платежа до получения одного из следующих конечных статусов:

- `paid` — платёж успешно оплачен.
- `cancelled` — платёж отменён.
- `expired` — срок действия платежа истёк.

При других статусах SDK продолжает ожидание и проверку платежа.

### Ошибки

SDK предоставляет исключение `PayTradeError`.

Оно содержит следующие поля:

- `code` — код ошибки.
- `status` — HTTP-статус ответа API. Для сетевых ошибок может быть равен `0`.

Коды ошибок, которые обрабатываются непосредственно SDK:

| Код | Описание |
|---|---|
| `network_error` | Не удалось подключиться к API или произошёл сетевой таймаут |
| `invalid_response` | API вернул ответ, который невозможно обработать как JSON |
| `http_error` | Общая ошибка HTTP, если API не предоставил собственный код |

При HTTP-ошибках API может возвращать собственный код и сообщение, которые SDK передаёт через `PayTradeError`.

## 10. Примеры использования

### Подключение

```python
import asyncio
from paytrade_sdk import PayTrade, PayTradeError

API_KEY = "YOUR_API_KEY"
BASE_URL = "https://a-ktj8.onrender.com"


async def main():
    async with PayTrade(API_KEY, BASE_URL) as api:
        account = await api.me()
        print(account)


if __name__ == "__main__":
    asyncio.run(main())
```

### Создание платежа

```python
payment = await api.create_payment(
    order_id="order_001",
    buyer_id=123456789,
    amount=10,
    title="Test purchase",
    description="Payment through PayTrade",
    return_payload="user_123",
    expires_in=3600
)

print(payment.id)
print(payment.payment_url)
print(payment.status)
```

`order_id` — уникальный идентификатор заказа в приложении разработчика.

`buyer_id` — числовой идентификатор покупателя, передаваемый API.

`return_payload` — дополнительная строка, передаваемая API вместе с данными платежа.

Метод `payment()` также позволяет создать платёж, используя альтернативный порядок аргументов:

```python
payment = await api.payment(
    title="Test purchase",
    amount=10,
    buyer_id=123456789,
    order_id="order_001"
)
```

### Проверка платежа

```python
payment_info = await api.get_payment(payment.id)

print(payment_info.status)
print(payment_info.paid)
print(payment_info.amount)
```

### Отмена платежа

Для отправки запроса на отмену используется `cancel_payment()`:

```python
cancelled_payment = await api.cancel_payment(payment.id)

print(cancelled_payment.status)
```

Метод возвращает объект `Payment` с актуальными данными, полученными от API.

### Ожидание оплаты

```python
payment_result = await api.wait_for_payment(
    payment.id,
    timeout=300
)

print(payment_result.status)
print(payment_result.paid)
```

По умолчанию проверка выполняется каждые 3 секунды.

Если время ожидания истечёт, SDK выбросит `TimeoutError`. Это не отменяет платёж: он остаётся в текущем состоянии. Для проверки его состояния можно использовать `get_payment()`.

### Обработка ошибок

```python
try:
    payment_result = await api.wait_for_payment(
        payment.id,
        timeout=300
    )

except PayTradeError as error:
    print("Error code:", error.code)
    print("HTTP status:", error.status)
    print("Message:", error)

except TimeoutError:
    print("Payment waiting timed out")
```

Для повторной отправки того же платёжного запроса используйте исходный `order_id`, чтобы избежать создания дублирующей операции.

## 11. Безопасность

При интеграции PayTrade API рекомендуется:

- Хранить API-ключ в конфиденциальном месте.
- Не публиковать ключ в открытых репозиториях.
- Не передавать ключ посторонним.
- Использовать HTTPS при подключении к API.
- Проверять результат оплаты перед выдачей товара или услуги.
- Не считать создание платежа подтверждением его оплаты.
