# PayTrade | README

**PayTrade** — екосистема інструментів для Telegram, що об'єднує маркетплейс, платіжну інфраструктуру, API та Python SDK.

Проєкт дозволяє користувачам розміщувати й купувати товари, проводити угоди та взаємодіяти з продавцями. Розробники можуть підключати платіжні можливості PayTrade до власних застосунків.

## 1. Про проєкт

PayTrade об'єднує кілька напрямів:

- **Маркетплейс** — платформа для продажу та купівлі товарів.
- **Платежі** — оплата через Telegram Stars і внутрішній баланс.
- **API** — можливість підключити PayTrade до сторонніх застосунків.
- **Python SDK** — бібліотека для зручної роботи з API.
- **Telegram-бот** — основний інтерфейс проєкту.

PayTrade розвивається як єдина екосистема, у якій користувацькі та технічні можливості доповнюють одна одну.

## 2. Екосистема

Основні компоненти проєкту:

- **Основний бот:** [@paytradebot](https://t.me/paytradebot)
- **Підтримка:** [@PayTradeSupportbot](https://t.me/PayTradeSupportbot)
- **API:** платіжний інтерфейс для сторонніх застосунків.
- **Python SDK:** інструмент для інтеграції API в Python-проєкти.

## 3. Маркетплейс

Маркетплейс дозволяє користувачам виступати як продавцями, так і покупцями.

Можливості платформи:

- Створення власних пропозицій.
- Перегляд каталогу товарів.
- Пошук за назвою.
- Перегляд профілів продавців.
- Купівля через внутрішній баланс або Telegram Stars.
- Спілкування з іншою стороною угоди.
- Підтвердження отримання товару.
- Залишення відгуків.

Нові товари проходять перевірку перед публікацією в каталозі.

## 4. Товари та каталог

### Розміщення товарів

Для створення пропозиції продавець вказує назву, додає фотографію та встановлює ціну в Telegram Stars.

Для одного продавця передбачено обмеження — до 10 товарів.

### Керування товарами

Власник пропозиції може:

- Змінити назву.
- Змінити ціну.
- Замінити фотографію.
- Видалити фотографію.
- Видалити товар.

### Каталог

У каталозі відображаються пропозиції, доступні для купівлі.

Користувачі можуть переглядати товари, переходити між сторінками та відкривати детальну інформацію.

Пріоритетні пропозиції відображаються вище за звичайні. Для товарів зі знижкою відображається її розмір та підсумкова ціна.

### Картка товару

У картці відображаються назва, вартість, інформація про продавця та фотографія, якщо її додано.

Звідси можна перейти до купівлі або відкрити профіль продавця.

## 5. Покупки та угоди

У PayTrade передбачено два способи оплати:

**Купівля через баланс**

Вартість товару списується з внутрішнього балансу покупця.

**Пряма купівля**

Покупець оплачує товар через Telegram Stars.

Після успішної оплати створюється замовлення та починається взаємодія між сторонами.

### Спілкування щодо замовлення

Покупець і продавець отримують сповіщення про купівлю та можуть обмінюватися повідомленнями через бота.

Продавець може повідомити про передачу товару, а покупець — підтвердити його отримання.

Після підтвердження покупцем угода завершується, а кошти зараховуються продавцю.

Купівля власного товару не підтримується.

## 6. Баланс і відгуки

### Внутрішній баланс

Баланс використовується для оплати товарів усередині маркетплейсу.

Продавець отримує кошти за завершену угоду після підтвердження отримання товару покупцем.

### Відгуки

Після завершення купівлі покупець може оцінити продавця за п'ятибальною шкалою та залишити відгук.

У профілі продавця доступна статистика оцінок. Також можна переглядати окремі відгуки з інформацією про товар, оцінку та дату.

## 7. PayTrade API

**PayTrade API** дозволяє розробникам використовувати платіжні можливості проєкту у власних застосунках.

За його допомогою можна:

- Підключати власні застосунки до PayTrade.
- Створювати платежі.
- Отримувати посилання для оплати.
- Перевіряти стан платежів.
- Отримувати інформацію про застосунок.

Платежі проводяться в Telegram Stars (`XTR`).

### Як працює оплата

1. Ваш застосунок створює замовлення.
2. Через API створюється платіж.
3. Застосунок отримує посилання для оплати.
4. Покупець переходить за посиланням до офіційного бота PayTrade.
5. Покупець оплачує замовлення.
6. Ваш застосунок отримує актуальну інформацію про платіж.
7. Після підтвердження оплати ваш застосунок виконує необхідні дії.

PayTrade надає платіжну інфраструктуру, а логіка самого стороннього застосунку залишається під контролем його розробника.

## 8. Python SDK

**PayTrade SDK** — офіційна Python-бібліотека для роботи з API.

Поточний публічний реліз — **v0.2.0**.

SDK підтримує асинхронну роботу та надає методи для:

- Підключення до API й отримання інформації про застосунок (`me()`).
- Створення платежів (`create_payment()`, `payment()`).
- Отримання інформації про платіж (`get_payment()`).
- Скасування платежу (`cancel_payment()`).
- Очікування результату оплати (`wait_for_payment()`).
- Обробки помилок API.

Бібліотека підходить для асинхронних Python-проєктів, зокрема Telegram-ботів на aiogram.

### Об'єкт Payment

Після створення або отримання платежу SDK повертає об'єкт `Payment`.

Основні поля:

| Поле | Опис |
|---|---|
| `id` | Ідентифікатор платежу |
| `order_id` | Ідентифікатор замовлення розробника |
| `buyer_id` | Ідентифікатор покупця, переданий під час створення платежу |
| `amount` | Сума платежу |
| `currency` | Валюта платежу |
| `title` | Назва платежу |
| `description` | Опис платежу |
| `status` | Поточний статус |
| `created_at` | Час створення |
| `expires_at` | Час завершення строку дії |
| `paid_at` | Час оплати, якщо платіж оплачено |
| `payment_url` | Посилання для оплати |
| `test_mode` | Ознака тестового режиму |

Додатково доступна властивість `paid`, яка повертає `True`, якщо статус платежу — `paid`.

### Статуси платежів

`wait_for_payment()` перевіряє стан платежу до отримання одного з таких кінцевих статусів:

- `paid` — платіж успішно оплачено.
- `cancelled` — платіж скасовано.
- `expired` — строк дії платежу завершився.

За інших статусів SDK продовжує очікування та перевірку платежу.

### Помилки

SDK надає виняток `PayTradeError`.

Він містить такі поля:

- `code` — код помилки.
- `status` — HTTP-статус відповіді API. Для мережевих помилок може дорівнювати `0`.

Коди помилок, які обробляються безпосередньо SDK:

| Код | Опис |
|---|---|
| `network_error` | Не вдалося підключитися до API або стався мережевий тайм-аут |
| `invalid_response` | API повернув відповідь, яку неможливо обробити як JSON |
| `http_error` | Загальна HTTP-помилка, якщо API не надав власний код |

У разі HTTP-помилок API може повертати власний код і повідомлення, які SDK передає через `PayTradeError`.

## 10. Приклади використання

### Підключення

```python
import asyncio
from paytrade_sdk import PayTrade, PayTradeError

API_KEY = "YOUR_API_KEY"
BASE_URL = "https://a-ktj8.onrender.com"


async def main():
    async with PayTrade(API_KEY, BASE_URL) as api:
        account = await api.me()
        print(account)


if __name__ == "__main__":
    asyncio.run(main())
```

### Створення платежу

```python
payment = await api.create_payment(
    order_id="order_001",
    buyer_id=123456789,
    amount=10,
    title="Test purchase",
    description="Payment through PayTrade",
    return_payload="user_123",
    expires_in=3600
)

print(payment.id)
print(payment.payment_url)
print(payment.status)
```

`order_id` — унікальний ідентифікатор замовлення в застосунку розробника.

`buyer_id` — числовий ідентифікатор покупця, який передається API.

`return_payload` — додатковий рядок, який передається API разом із даними платежу.

Метод `payment()` також дозволяє створити платіж, використовуючи альтернативний порядок аргументів:

```python
payment = await api.payment(
    title="Test purchase",
    amount=10,
    buyer_id=123456789,
    order_id="order_001"
)
```

### Перевірка платежу

```python
payment_info = await api.get_payment(payment.id)

print(payment_info.status)
print(payment_info.paid)
print(payment_info.amount)
```

### Скасування платежу

Для надсилання запиту на скасування використовується `cancel_payment()`:

```python
cancelled_payment = await api.cancel_payment(payment.id)

print(cancelled_payment.status)
```

Метод повертає об'єкт `Payment` з актуальними даними, отриманими від API.

### Очікування оплати

```python
payment_result = await api.wait_for_payment(
    payment.id,
    timeout=300
)

print(payment_result.status)
print(payment_result.paid)
```

За замовчуванням перевірка виконується кожні 3 секунди.

Якщо час очікування мине, SDK викличе `TimeoutError`. Це не скасовує платіж: він залишається в поточному стані. Для перевірки його стану можна використовувати `get_payment()`.

### Обробка помилок

```python
try:
    payment_result = await api.wait_for_payment(
        payment.id,
        timeout=300
    )

except PayTradeError as error:
    print("Error code:", error.code)
    print("HTTP status:", error.status)
    print("Message:", error)

except TimeoutError:
    print("Payment waiting timed out")
```

Для повторного надсилання того самого платіжного запиту використовуйте початковий `order_id`, щоб уникнути створення дублюючої операції.

## 11. Безпека

Під час інтеграції PayTrade API рекомендується:

- Зберігати API-ключ у конфіденційному місці.
- Не публікувати ключ у відкритих репозиторіях.
- Не передавати ключ стороннім особам.
- Використовувати HTTPS під час підключення до API.
- Перевіряти результат оплати перед видачею товару або послуги.
- Не вважати створення платежу підтвердженням його оплати.
